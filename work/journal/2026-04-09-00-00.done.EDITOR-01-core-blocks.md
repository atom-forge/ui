## Implementation Log

### 2026-04-09

**Component created:** `src/lib/controls/forms/block-editor/` — `types.ts`, `BlockEditor.svelte`, `index.ts`

**Export name:** `MdBlockEditor` (not `BlockEditor`). The existing `editors/block-editor/` already exports `BlockEditor`, causing a conflict in `src/lib/index.ts`. Renamed the new component's export to `MdBlockEditor` and types namespace to `MdBlockEditorTypes` to avoid ambiguity.

**State management:** Two `$effect`s handle bidirectional sync:
- Effect 1 (`blocks` → `value`): serializes on every block mutation, writes to `lastSerialized` before writing `value` to prevent Effect 2 loop.
- Effect 2 (`value` → `blocks`): re-parses only when `value !== lastSerialized`, detecting parent-driven resets (e.g., Reset button) without re-triggering from Effect 1's writes.

**Contenteditable DOM strategy:** `initBlock` action (fire-once, no `update`) sets `innerText` on block creation. Svelte never re-renders block content reactively — content changes from user input are synced back to state via `oninput`. Programmatic content changes (Enter split, Backspace merge) update both state and DOM explicitly.

**Shift+Enter:** Uses `document.execCommand('insertText', false, '\n')` for cross-browser consistency. With `whitespace-pre-wrap`, the `\n` renders as a visual line break and `innerText` reads it back correctly.

**Cursor placement:** After Enter, a `setTimeout` queries the new block by `data-block-id` and sets the cursor to start. After Backspace merge, sets the previous block's cursor to `prevContent.length` using a TreeWalker over text nodes.

**`bun run check`:** 0 errors, 0 warnings.
