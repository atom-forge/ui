## Request

Provide a flat, alternative `UI` namespace for the existing public components and their context-bound manager APIs, preserving named exports.

## What Was Done

- Added `src/lib/ui.ts`, explicitly referencing 161 existing public components and UI API functions. No component implementations were copied and no dependencies were added.
- Re-exported `UI` from `src/lib/index.ts` without changing existing named exports.
- Included core and helper components, control components and their public companion components, theme and overlay manager APIs, checkbox group manager APIs, and `getBlockAPI`.
- Kept types, general-purpose helpers, and utility namespaces as separate named exports.
- Added explicit readonly `typeof` property annotations to preserve original signatures, including generic Svelte components, and allow declaration generation without private Svelte type naming errors.
- Documented namespace usage, provider/context requirements, modal access, and tree-shaking caveats in `docs/guides/getting-started.md`.

## Notes

- Manager instances are still retrieved from the current component context. The namespace does not introduce global overlay state.
- All 161 namespace members were loaded using Vite SSR and verified to match their corresponding named exports by reference; all were defined.
- `bun run prepack` passed after explicit typing resolved initial declaration generation warnings. The generated `dist/ui.d.ts` retains original component and manager types.
- `bun run build` passed.
- `bun run check` reported the same 23 errors in 11 files as before this change; no errors were reported for the namespace.
- `git diff --check` passed.
- Namespace imports may retain more code than direct named imports; no equivalent tree-shaking guarantee is made.
