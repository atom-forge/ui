## Implementation Log

### Decisions

**Separate `highlight.ts` module**
The regex parser lives in `src/lib/controls/forms/block-editor/highlight.ts` as a pure function `highlight(text: string): string`. No DOM dependency — easy to unit-test in isolation.

**`data-hl` attribute + Svelte `:global()` CSS**
Dynamically-injected `<span>` tags carry a `data-hl` attribute (e.g. `data-hl="heading"`). Styles are defined in the Svelte component's `<style>` block using `:global([data-hl="..."])`. This avoids Tailwind purging issues (dynamic class names are not scanned at build time) and keeps colors in CSS custom properties (`var(--color-accent)`, etc.) — fully theme-aware, no hardcoded hex.

**`applyHighlight(el, content)` helper**
Saves cursor offset via `getCursorOffset` (pre-DOM-change), sets `el.innerHTML = highlight(content)`, then calls `setCursorPosition` to restore the cursor. The existing `TreeWalker`-based cursor helpers work correctly after span injection because they operate on text nodes (which span wrappers do not affect).

**`initBlock` updated to set `innerHTML`**
Changed from `node.innerText = content` to `node.innerHTML = highlight(content)`. All subsequent imperative DOM updates (Enter split, Backspace merge) also use `innerHTML = highlight(...)`.

**`oninput` reads `innerText` before highlighting**
Setting `innerHTML` does not trigger a new `input` event on a contenteditable, so there is no feedback loop. `innerText` of a span-annotated element still returns the plain text, so the block state stays in sync.

**Inline code regex order**
Inline code is processed first (before bold/italic) to prevent `*` or `**` inside backticks from being misinterpreted as emphasis markers.

**Heading regex requires a space**
`/^(#{1,6})( .+)?$/` — only highlights if `#` is followed by a space and content. Bare `#nospace` is treated as a regular line.
