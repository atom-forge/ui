**Key architectural decisions:**

1. **`Block.focused` is the single source of truth** for edit vs. preview mode. `{#if block.focused}` in the template drives the DOM swap — no separate "active index" variable.

2. **Preview div and edit div share identical CSS classes** (`blockContentCls`): same font, size, leading, padding. This is the no-layout-shift guarantee.

3. **`initEditBlock` use: action** — runs once when the edit div is mounted (i.e. on focus). Sets highlighted innerHTML, focuses the element, and places the cursor at a stored offset. Offset is passed via a non-reactive `pendingCursors: Map<string, number>` side-channel to avoid Svelte reactivity entanglement.

4. **`onBlur` uses `setTimeout(0)`** to defer the unfocus, allowing a same-tick `focusBlock()` call (from clicking another block's preview) to cancel the blur effect. Without this, clicking from block A to block B would briefly flash both in preview mode.

5. **`detectType` maps to `BlockType` literals** — `todo-list` is detected before `bullet-list` (since `- [ ]` matches both patterns; order matters).

6. **`preview.ts` is pure** — no Svelte/DOM imports. `renderPreview` handles all 8 block types. For EDITOR2-02, individual block Svelte components will replace this function per type.

7. **`BlockPlugin` system removed** — v2's architecture is component-based per block type (EDITOR2-02), not a plugin registry. Plugin files were deleted to avoid type errors.

8. **Import depth bug fixed**: `src/lib/dev/<editor>/` is depth-3, not depth-4 like controls. `../../helpers/types.ts` is correct (not `../../../`).
